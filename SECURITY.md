# Security

## Security Policy

SecureForge is a security-focused project designed for authorized security verification, vulnerability assessment, validation, and release-gate workflows.

Security issues affecting the project itself should be reported responsibly so they can be investigated and addressed.

## Vulnerability Reporting

If you discover a security vulnerability in SecureForge, please report it privately rather than publicly disclosing the issue before it has been reviewed.

A vulnerability report should include:

* A clear description of the vulnerability.
* The affected component, file, or functionality.
* Steps required to reproduce the issue.
* Expected behavior.
* Actual behavior.
* Relevant logs, error messages, or other evidence.
* Any potential security impact you identified.

## Report Handling

Security reports will be reviewed to determine:

1. Whether the reported behavior represents a security vulnerability.
2. Which component or workflow is affected.
3. The potential impact and severity.
4. Whether a remediation or mitigation is required.

Please avoid including sensitive credentials, private keys, access tokens, or other secrets in a vulnerability report.

## Responsible Disclosure

Please allow reasonable time for a security issue to be investigated and addressed before publicly disclosing technical details.

Security testing of SecureForge or any integrated target should only be performed against systems and applications for which you have explicit authorization.
